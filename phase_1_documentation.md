# Optimal Execution Engine: Phase 1 Documentation

This document explains the technical implementation and mathematical logic behind Phase 1 of our system architecture: **Data Acquisition & Environment**.

## Overview of Phase 1

The goal of Phase 1 is to build the foundational sandbox where our Reinforcement Learning (RL) agent will learn to trade. To train an RL agent, we need two things:
1. **A Data Feed**: Historical data representing the state of the market.
2. **A Simulation Engine**: A set of rules defining how the market reacts when the agent decides to place an order. 

---

## 1. The Data Pipeline (`loader.py`)

The `DataLoader` class is responsible for reading raw historical limit order book data (in `.csv` or `.parquet` formats) and normalizing it into a clean, time-indexed DataFrame.

### Microstructural Features Extracted:
Beyond simply reading the prices, the loader calculates specific features that help the RL agent understand the *current state of liquidity*:

- **Mid-Price**: The theoretical fair value of the asset at a given microsecond.
  $$ \text{Mid Price} = \frac{\text{Bid Price} + \text{Ask Price}}{2} $$
- **Spread**: The cost of crossing the order book. A wider spread means lower liquidity and higher immediate transaction costs.
  $$ \text{Spread} = \text{Ask Price} - \text{Bid Price} $$
- **Order Book Imbalance (OBI)**: This is a critical microstructural signal. It measures the pressure at the top of the order book. 
  $$ \text{OBI} = \frac{\text{Bid Volume} - \text{Ask Volume}}{\text{Bid Volume} + \text{Ask Volume}} $$
  - **Why it matters**: If OBI is heavily positive (close to +1), there is massive buying pressure. The RL agent can learn to use this signal to delay selling (hoping for a better price) or accelerate buying (before the price runs away).

## 2. The Simulation Environment (`execution_env.py`)

This is the core of Phase 1. We built a custom subclass of `gymnasium.Env`. Standardizing the environment to the Gym API allows us to easily plug in advanced Deep RL algorithms (like DDPG or PPO) later.

### The RL Framework
- **State (Observation Space)**: At each step, the agent looks at: `[Time Remaining, Inventory Remaining, Mid-Price, Spread, OBI]`. 
- **Action (Action Space)**: The agent outputs a continuous number between `0.0` and `1.0`, representing the *fraction* of its remaining inventory it wants to execute *right now*.
- **Reward**: The reward is the cash flow generated by the trade, minus any penalties (such as failing to liquidate everything before time runs out).

### The Market Impact Engine (The SDE Logic)

If we just let the agent trade at the historical mid-price, it would learn a "cheat" policy: it would dump all 10,000 shares at the very first timestep because it assumes infinite liquidity. In reality, large market orders eat through the order book and get terrible prices. 

To simulate this accurately without needing a full Level 3 Limit Order Book reconstructor, we implemented the **Almgren-Chriss Market Impact Model** directly into the `step()` function.

When the agent decides to execute a volume $v$:

#### A. Temporary Impact ($h(v)$)
This represents the immediate liquidity cost of crossing the spread and eating into deeper price levels. It penalizes the *execution price* of the current trade, but does not affect the fundamental price of the asset.
$$ \text{Temporary Impact} = \kappa \cdot v $$
- $\kappa$ (Kappa): The temporary impact coefficient. 
- **Effect**: If the agent trades too aggressively (high $v$), it receives a much worse execution price.

#### B. Permanent Impact ($g(v)$)
This represents the information leakage of our trades. When we submit a large order, high-frequency traders and market makers adjust their quotes. This permanently moves the *baseline mid-price* against us for all future timesteps in the episode.
$$ \text{Permanent Impact} = \gamma \cdot v $$
- $\gamma$ (Gamma): The permanent impact coefficient.
- **Effect**: We maintain a `permanent_impact_acc` state variable. Every time we buy, we push the historical mid-price slightly higher for the rest of the episode. 

### Putting it Together: The Execution Price

When the agent steps forward, the actual price it gets for its order is calculated as:
$$ \text{Execution Price} = S_t^{\text{historical}} + \sum (\text{Past Perm Impact}) \pm \frac{\text{Spread}}{2} \pm (\kappa \cdot v) $$

This mathematical sandbox forces the RL agent to learn a delicate balance:
- **Trade too fast?** You get destroyed by Temporary Impact ($\kappa$).
- **Trade too slow?** You face market risk (the price might drift away) and accumulate Permanent Impact ($\gamma$).

This creates the exact optimization problem that the Almgren-Chriss closed-form solver (which we will build in Phase 2) attempts to solve mathematically!
